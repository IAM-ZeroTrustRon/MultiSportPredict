## 1. What this project is

A multi-sport handicapping system. For one exact fixture it:

1. resolves the fixture against an official schedule source (never a name guess),
2. builds pregame features from earlier completed games only,
3. produces a score/probability projection from a sport-specific model,
4. attaches captured sportsbook quotes (bookmaker, market, line, side, timestamp),
5. derives fair probabilities, pushes and estimated EV from the model distribution,
6. writes an explicit recommendation (`BET` / `LEAN` / `PASS` / `INFO` / `VOID`),
7. stores everything in one SQLite database, and
8. grades the saved selection later against the official final.

The organizing principle is **price first, not pick first**: an unpriced
simulation is not an edge, and a projection the system cannot validate is stored
as `INFO` and kept out of the betting record. Nothing here places wagers.

Key honesty rules the whole codebase is built around — keep them:

- Missing data is *unavailable*, never zero, 50%, or a median filler.
- A model that cannot validate a component emits projection-only output.
- Saved runs are immutable; `show`/`push` replay the stored snapshot.
- Source retrieval timestamps, provenance and limitations travel with the data.
- Research output, delivered recommendations and real bets stay separate.

### 2b. Dynamic position sizing

`models/score_ratings.price_market` (shared by NHL, NCAAF, NBA/WNBA/NCAAB,
EuroLeague, KBL/BBL/NZNBL and tennis) now returns `fair_prob_a`/`fair_prob_b`
from a power-method de-vig of the offered pair, plus `stake_size`: a quarter of
full Kelly on the model probability, capped at 5% of bankroll. EV and the 5%
LEAN gate are untouched and still use the model probability; sizing off the
de-vigged probability would price the market against itself and never stake.
`stake_size` is `None` for missing prices, below-gate markets, integer lines with
push mass and projection-only rows.

The value persists in a new `predictions.stake_size` column (migrated by
`init_db`, accepted as a keyword by `store_prediction`, forwarded by
`run_ncaaf.store`). `msp.py record` gains `quarter_kelly_decisions`: weighted P/L
and ROI over a fixed notional bankroll, with rows that never stored a stake
counted as excluded rather than defaulted to one unit. The flat recorded-price
block is unchanged so historical figures stay comparable.

## 4. How it is built

```
msp.py ──► msp_workflow.py ──► subprocess: venv/Scripts/python.exe <runner>
             │                                   │
             │  refresh_plan()                    │ ingest_* → data sources
             │  run_command()                     │ features → models → market
             │  grade_all()                       │ core.historical_storage
             ▼                                   ▼
        workflow_runs / workflow_deliveries    predictions (+ raw_json snapshot)
             │                                   │
        show / push (immutable replay)      grade_predictions --auto
             ▼                                   ▼
        score_review + embed_builder ──► Discord    record / pending / reports
```

Design invariants:

- **One canonical module per concern.** `core/historical_storage.py` is the only
  store; `core/market_handicapper.py` the only de-vig/EV math; `embed_builder.py`
  the only card shape. Add to these, do not fork parallel versions.
- **Runner isolation.** `msp_workflow.run()` shells out to the sport runner with
  `MSP_RUN_ID` in the environment, rejects past dates, and blocks
  `--push/--discord/--no-fixture-check` escape hatches. It saves a snapshot even
  on failure (status `failed`) so a bad run is auditable.
- **Atomic writes.** Stores and caches write to `.tmp`/`.download` and `replace()`
  only after validation, so a failed download cannot destroy the last good cache.
- **Model artifacts are versioned.** NHL artifacts carry `data_hash`,
  `feature_version`, `feature_schema` and `trained_before`; a mismatch refuses
  inference instead of silently scoring with the wrong contract.
- **Gates suppress rather than guess.** A gate that cannot be satisfied turns the
  row into `INFO`, nulls EV/picks and keeps it out of the betting record.

## 5. How it works, practically

**Refresh and grade everything**

```bash
venv/Scripts/python.exe -u msp.py daily --all      # refresh + grade
venv/Scripts/python.exe -u msp.py refresh --all    # ingest only
venv/Scripts/python.exe -u msp.py grade --all      # grade only
```

`refresh_plan()` runs independent stages (NHL, MLB, KBO, soccer, tennis, NFL,
NCAAF, basketball, table tennis). A failing stage does not stop the others; the
summary records exit codes and per-stage logs under `output/workflow/`.

**Run a fixture, review it, optionally deliver it**

```bash
venv/Scripts/python.exe -u msp.py run --sport nhl --match "Florida Panthers vs Chicago Blackhawks" --date 2026-10-25
venv/Scripts/python.exe -u msp.py show --latest        # immutable saved review
venv/Scripts/python.exe -u msp.py push --latest        # sends to Discord
venv/Scripts/python.exe -u msp.py record               # W-L-P, units, ROI
venv/Scripts/python.exe -u msp.py record --all-time
venv/Scripts/python.exe -u msp.py pending
```

`show` picks the latest successful run across all sports — check the sport and
matchup before pushing. `push` never re-runs a model.

**Grading.** `grade_predictions.py --auto` fetches official results per sport
(including `nhl_sources.schedule`), verifies the official event ID where stored,
settles each market by that market's own rules, and takes a database backup first.
NHL rows require `settlement.scope == "official_final_including_ot_so"`; a
three-way or regulation-only market is left ungraded rather than conflated.

**Records.** `record` takes the newest row per fixture, excludes `PASS/INFO/VOID`
and duplicate reruns, and reports the recorded-price subset separately (one unit
per selection, pushes included; win rate excludes pushes). Its
`quarter_kelly_decisions` block re-weights those same selections by the stored
`stake_size` against a fixed notional bankroll. It is a model record, not proof
of wagers.

## 9. Conventions to keep

- Bash syntax on Windows (`mv`, `rm`, `/dev/null`); forward slashes in paths.
- Fixture dates are America/New_York; every stored timestamp is timezone-aware UTC.
  A naive timestamp raises.
- Matchups are written `"Home Team vs Away Team"` — home first.
- Back up the database before anything destructive; `workflow_backup()` and
  `workflow_cleanup()` exist for this. Nothing in this codebase deletes history.
- Do not invent metrics, medians, or starter identities to make a model run.
- New behaviour needs a test that fails on the old behaviour, and an update to the
  affected command reference and data contract. Update `INDEX.md`,
  `STATE_OF_MODEL.md` and this file when structure changes.
